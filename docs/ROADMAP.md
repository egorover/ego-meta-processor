# 🗺 ROADMAP: EgoMeta Processor

**Версия:** 1.0.0 | **Дата:** 31.10.2026  
**Автор:** Александр Егоров (Alex Egorov)  
**Цель документа:** Стратегическое развитие проекта от Production-Ready MVP (v.3) к AI-native enterprise-решению.

---

## 🎯 Vision

Превратить EgoMeta Processor в **AI-native платформу автоматизации заказов**, где создание, отладка и тестирование бизнес-логики происходит **по промпту пользователя** через диалоговый интерфейс, а система самостоятельно поддерживает свою работоспособность.

---

## 📅 Phase 1: Automation Grade-Up (v.4, Q1 2027)

**Фокус:** Полноценное автоматизированное тестирование.

### 1.1. Детерминированный Test Runner
*   **Переход на production webhook** (`/webhook/order-v2`) с активной воркфлоу.
*   **Асинхронный polling результатов:** скрипт отправляет запрос и ждёт появления записи в `orders`/`log` через NocoDB API (timeout + retry).
*   **Идемпотентные тестовые run_id** для точной сверки результатов.
*   **Детальный отчёт** в формате JUnit XML / HTML для CI.

### 1.2. CI/CD интеграция
*   **GitHub Actions** для автоматического запуска TR/SBT при каждом PR.
*   **Статусные бейджи** в README (passing/failing).
*   **Тестовые артефакты** (скриншоты таблиц, логи) сохраняются в GitHub Artifacts.

### 1.3. Self-contained тестовая среда
*   **Docker Compose** для изолированной тестовой среды (n8n + NocoDB + Postgres).
*   **Фикстуры данных** с автоматической загрузкой через API.
*   **Транзакционный откат** после каждого прогона.

### 1.4. Покрытие кода
*   **80%+ coverage** всех ветвлений логики.
*   **Property-based testing** для генерации edge-cases.
*   **Mutation testing** для проверки качества самих тестов.

## 📅 Phase 2: Product-Grade Evolution (Q2 2027)

**Фокус:** Превращение в полноценный продукт для бизнеса.

### 2.1. UI для очереди ревью
*   **React/Next.js** приложение с фильтрами, сортировкой, поиском.
*   **Real-time обновления** через WebSocket (новые заказы появляются мгновенно).
*   **Bulk-операции:** подтвердить/отклонить несколько заказов разом.
*   **Комментарии и история** решений по каждому заказу.

### 2.2. Продуктовая таблица цен
*   **Динамический каталог** в NocoDB (таблица `prices` с полями `sku`, `name`, `price_rub`, `stock`).
*   **Промпт генерируется** из актуального каталога перед каждым запросом.
*   **Остатки на складе** влияют на доступность (недоступные товары → `needs_review`).
*   **История изменения цен** для аудита.

### 2.3. Мониторинг и аналитика
*   **Grafana дашборды:**
    *   Стоимость LLM-вызовов по дням/клиентам
    *   Среднее время обработки заказа
    *   % заказов в статусе `needs_review`
    *   Топ причин отклонений
*   **Алерты** при превышении бюджета на LLM (порог: 1000₽/день).

### 2.4. Безопасность и надёжность
*   **Unique constraint** на `idempotency_key` в Postgres (защита от гонок на уровне БД).
*   **Rate limiting на уровне Nginx/Envoy** (защита от DDoS).
*   **Шифрование PII** (персональных данных клиентов) в БД.
*   **Аудит-лог** всех действий менеджеров в очереди ревью.

### 2.5. Интеграции
*   **CRM-система** (AmoCRM, Bitrix24) для автосоздания сделок.
*   **Курьерские службы** (СДЭК, Boxberry) для автоматического оформления доставки.
*   **SMS/WhatsApp** через отдельные каналы (как альтернатива Telegram).

## 📅 Phase 3: AI-Native Development (Q3–Q4 2027)

**Фокус:** Использование AI для разработки самой системы.

### 3.1. Prompt-Driven Workflow Generation
*   **Chatbot-интерфейс** для бизнес-пользователей:
    > "Добавь проверку, что клиент из Москвы не может заказать больше 5 позиций"
*   **LLM-агент генерирует** новый фрагмент n8n workflow (JSON).
*   **Автоматический merge** в основную схему с проверкой валидности.
*   **Визуализация изменений** до применения (diff).

### 3.2. Conversational Debugging
*   **Диалоговый дебаггер:**
    > "Почему заказ от boris@test.ru получил статус needs_review?"
*   **LLM анализирует** логи, таблицы, execution history.
*   **Предлагает гипотезы** с доказательствами.
*   **Автоматический фикс** простых проблем (например, добавить SKU в каталог).

### 3.3. Self-Healing Workflows
*   **LLM-монитор** постоянно анализирует поток выполнений.
*   **Автодетект аномалий:**
    *   Резкий рост `needs_review`
    *   Новые типы ошибок LLM
    *   Изменение паттернов клиентских сообщений
*   **Автогенерация фиксов** (например, расширить regex-классификатор ошибок).
*   **Человек в цикле:** менеджер подтверждает фикс через UI.

### 3.4. Auto-Testing через LLM-агента
*   **LLM-тестировщик** самостоятельно:
    *   Генерирует новые тестовые кейсы на основе изменений в бизнес-логике.
    *   Запускает прогоны через Test Runner.
    *   Анализирует расхождения между ожиданиями и фактом.
    *   Обновляет `TESTING_PROTOCOL.md` при легитимных изменениях поведения.
*   **Regression detection:** автоматически помечает коммиты, ломающие тесты.

### 3.5. Prompt Library & Versioning
*   **Версионирование системных промптов** как кода (Git).
*   **A/B тестирование** разных версий промптов на части трафика.
*   **Метрики качества** для каждого промпта (accuracy, cost, latency).
*   **Автоматический откат** при деградации метрик.

## 📅 Phase 4: Enterprise Scale (2028)

**Фокус:** Масштабирование до enterprise-решения.

### 4.1. Мультитенантность
*   **Изолированные пространства** для разных бизнесов.
*   **Отдельные credentials, БД, каталоги цен**.
*   **Billing** по использованию (заказы + LLM-токены).

### 4.2. Multi-channel ingestion
*   **Email-парсинг** (IMAP + LLM для извлечения заказов).
*   **Голосовые сообщения** (Speech-to-Text → обработка).
*   **Web-форма** с валидацией на клиенте.
*   **API для партнёров** (Swagger/OpenAPI 3.0).

### 4.3. Мультиязычность
*   **LLM-перевод** входящих заказов с любого языка.
*   **Локализованные каталоги** и промпты.
*   **Автодетект языка** клиента.

### 4.4. Продвинутая аналитика
*   **Customer Lifetime Value** (CLV) на основе истории заказов.
*   **Предиктивная аналитика:** что клиент закажет в следующий раз.
*   **Сегментация клиентов** для таргетированных коммуникаций.
*   **А/B тестирование** маркетинговых гипотез.

### Технологические предпосылки:

1.  **LLM с длинным контекстом** (1M+ токенов) для понимания всего проекта.
2.  **Tool-use capabilities** для взаимодействия с n8n, NocoDB, Git.
3.  **Multi-agent архитектуры:** Planner, Coder, Tester, Reviewer.
4.  **Sandbox-окружения** для безопасного выполнения изменений.
5.  **Feedback loop** с пользователем на каждом значимом шаге.

### Вызовы:

*   **Детерминизм:** LLM не всегда генерирует идентичный код.
*   **Безопасность:** риск injection через промпт.
*   **Отладка:** сложно понять, почему AI принял то или иное решение.
*   **Стоимость:** массовые вызовы LLM могут быть дорогими.
