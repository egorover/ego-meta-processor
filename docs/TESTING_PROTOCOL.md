## 2. Здоровый прогон (Регрессия)

**Цель:** убедиться, что штатные сценарии работают и данные пишутся в NocoDB.

### Порядок действий
1. Откройте **3.06.11 Qwe - TR - Test Runner**.
2. Убедитесь, что **3.06.10 Qwe - OP** открыт и нода «Приём заказа» в режиме **Listen for Test Event**.
3. Нажмите **Test workflow**.
4. Проверьте **«Сводка результатов»**: коды `200`, `422`, `413`, `508` допустимы; `500`/`502` — нет.

### Ожидаемые результаты

#### Таблица `orders`
- Каталог + адрес → `status = done`, `review_reason` пусто.
- Без адреса → `needs_review`, `review_reason = no_address`.
- Неизвестный товар → `needs_review`, `review_reason = unknown_items:N`.
- Дубликат → новая строка не создаётся.
- `error_code`, `error_message`, `retry_payload` пусты (модель штатна).

#### Таблица `log`
- Для путей, проходящих через «Сборку журнала1»: стадии `validate/llm/parse` с `http_code` и кодами ошибок для rejected.
- ⚠️ Примечание MVP: покрытие лога для отсечённых потоков нестабильно (см. раздел 4). Отсутствие строки лога для rejected-исхода в отдельном прогоне — известный дефект, а не ошибка оператора.

## 3. SBT: Smoke Broken Tests

**Цель:** подтвердить корректную обработку сбоев.  
**Критерии приёмки в v.2:** код HTTP-ответа в сводке SBT, состояние таблицы `orders`, Telegram-алерт. **Записи в `log` не проверяются** (раздел 4).

### ⚠️ ЖЕЛЕЗНОЕ ПРАВИЛО ПОСЛЕДОВАТЕЛЬНОСТИ
Одна поломка за цикл: сломал А → раскомментировал А → запустил → проверил → починил А → закомментировал А. Только потом Б.

### Тест T6_SBT: Авария LLM (Transport Error)

**Подготовка:**
1. В **3.06.10 Qwe - OP** откройте ноду **YandexGPT**.
2. В поле **Model** укажите несуществующую модель: `gpt://b1g5ro79nraja33819n8/yandexgpt/nonexistent-model-v999`. Сохраните.
3. В **3.06.12 Qwe - SBT**, нода **«Генерация SBT»**, раскомментируйте блок T6 (`sbt_fedor@test.ru`). Сохраните.

**Запуск:** убедитесь, что OP слушает вебхук; запустите SBT.

**Ожидаемый результат (критерии приёмки v.2):**
- **Output SBT:** код `502`.
- **orders:** строка `sbt_fedor@test.ru` со `status = failed`, `error_code = llm_unavailable`, `review_reason = llm_failed:llm_unavailable`, заполненным `retry_payload`.
- **Telegram:** алерт «🔴 Заказ не обработан» с кодом ошибки.
- **log:** в v.2 не проверяется (запись может отсутствовать — архитектурное ограничение).

**Откат (ОБЯЗАТЕЛЬНО):** вернуть модель `.../yandexgpt/latest`; закомментировать T6; удалить строку `sbt_fedor@test.ru` из `orders`.

### Тест T7_SBT: Circuit Breaker (Мягкий выключатель)

**Подготовка:**
1. NocoDB → `settings` → `orders_enabled = false`.
2. В **«Генерация SBT»** раскомментируйте блок T7 (`sbt_switch@test.ru`). Сохраните.

**Запуск:** убедитесь, что OP слушает вебхук; запустите SBT.

**Ожидаемый результат (критерии приёмки v.2):**
- **Output SBT:** код `503`.
- **Ответ клиенту:** тело `{"status":"rejected","order_id":"...","errors":["processing_disabled"]}`.
- **orders:** новая строка НЕ создана.
- **log:** в v.2 запись НЕ создаётся (наблюдаемый факт; поток отсекается до ноды журнала). Не является провалом теста.

**Откат (ОБЯЗАТЕЛЬНО):** `orders_enabled = true`; закомментировать T7.

## 4. Архитектурное ограничение v.2: частичное логирование

**Проблема:** нода «Сборка журнала1» расположена после «Ответ клиенту».  
**Наблюдения:** в здоровых TR-прогонах rejected-строки в `log` присутствовали; в SBT-прогонах (T6/T7) записей в `log` нет. Покрытие лога для отсечённых и аварийных потоков **нестабильно** и зависит от пути выполнения.  
**Следствие:** `log` в v.2 не может служить источником истины для аудита отказов; источник истины для SBT — HTTP-ответ, `orders`, Telegram.  
**План (v.3):** перенос «Сборки журнала1» сразу после «Проверки дубля и лимита» — запись лога до любых ветвлений и до ответа клиенту.

## 6. Типичные ошибки и решения

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `ERR_DATABASE_OP_FAILED` при PATCH | Нет колонки `review_reason` или `http_code` | Создать колонки до запуска |
| T6 не падает | Кэш кредов/модели n8n | Пересохранить credential, перезапустить n8n |
| T7 создаёт заказ | `orders_enabled` не применён | Проверить значение, обновить страницу |
| Дубли создают строки | Изменился текст/контакт | Байт-в-байт идентичные данные |
| SBT-сводка `unknown_test → N/A` | Пустой массив генерации или нет `url` | Раскомментировать тест целиком (включая `{`), проверить `return` один раз |
| Нет записей в `log` при SBT | Архитектурное ограничение v.2 | Норма для v.2; критерий приёмки — не `log`; исправляется в v.3 |

## 7. Глоссарий

- **SBT (Smoke Broken Test)** — изолированный набор тестов путей обработки ошибок.
- **Circuit Breaker** — аварийное отключение приёма заказов флагом в БД.
- **Review Reason** — машиночитаемая причина `needs_review`.
- **Idempotency Key** — ключ запроса, предотвращающий дубли.
- **Transport / Format / Schema Error** — три типа отказа LLM-интеграции.
