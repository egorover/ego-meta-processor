## 1. Цель и объём работы

Развернуть на сервере производственный пайплайн приёма заказов, изложенных свободным текстом, и извлечения из них структурированных данных (SKU и количество, адрес доставки, срочность) с помощью ИИ-агента на YandexGPT. Стек: n8n (оркестрация) + NocoDB (хранение) + YandexGPT (разбор) + Telegram (алерты).

Работа выполнена итерациями: **v.2 (MVP)** → анализ ограничений → **v.3 (production-grade)** с полным закрытием требований ТЗ.

**Ключевые инженерные решения v.3:**
1. **Triple Journaling** — запись в `log` до точек ветвления: любой исход (`rejected`, `duplicate`, `rate_limited`, `failed`) гарантированно аудируем. Дефект v.2 (потеря логов отсечённых потоков) устранён.
2. **Материализация дублей** — статус `duplicate` создаёт аудит-строку в `orders` со ссылкой на исходный заказ; модель не вызывается.
3. **Детерминированная классификация ошибок LLM** — regex-парсер сообщения об ошибке вместо второго вызова модели.
4. **Разделение ответственности отказов** — бизнес-ошибки модели обрабатывает красная ветка агента (502 + retry_payload); инфраструктурные крахи перехватывает отдельный Error Workflow.

**Режим тестирования:** в v.3 рекомендуется ручное тестирование готовыми PowerShell-командами (протокол v1.2.1): тестовый вебхук n8n возвращает ответ до записи в NocoDB, что создаёт race condition при автопрогонах. Полноценное автотестирование — цель v.4 (ROADMAP, Phase 1).

## 5. Честные ограничения и статус

* **Автотесты:** ручные (см. выше); CI/CD отсутствует.
* **Инфраструктура:** единственные инстансы n8n/NocoDB, без TLS/резервирования/бэкапов — поэтому работа позиционируется как **опытная эксплуатация**, а не полная промышленная (подробная самооценка — в README, разд. 1.1).
* **Продукт:** ревью-очередь без UI; цены зашиты в промпт; нет unique-констрейнта идемпотентности.
* Все ограничения осознаны, задокументированы и распределены по фазам `docs/ROADMAP.md`.

## 6. Эволюция v.2 → v.3 (что даёт эта итерация)

| Проблема v.2 | Решение в v.3 |
|:---|:---|
| Журнал после ответа клиенту → потеря логов отсечённых потоков | Triple Journaling: запись до ветвлений |
| Дубль не виден в БД (только в HTTP-ответе) | Аудит-строка `duplicate` + `retry_payload` |
| Нет отдельного Error Workflow (п.8) | `3.06.14` из 3 нод, подключён и проверен индуцированным крахом |
